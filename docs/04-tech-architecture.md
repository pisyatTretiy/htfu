# 04. Техническая архитектура

## 4.1 Выбор стека

### Рекомендация: TypeScript + PixiJS 8 + Vite, собственная 2D-физика

| Критерий | Оценка |
|---|---|
| Вес билда | ~1 МБ движка + ассеты → реально уложиться в 15–25 МБ при лимите 100 МБ |
| Старт игры | Первый экран < 3 сек на 4G — критично для удержания на портале |
| Мобильная производительность | WebGL-батчинг PixiJS даёт 60 FPS на бюджетных Android при 2D-сцене |
| Контроль над SDK | Прямая интеграция без прослоек плагинов, полный контроль над `LoadingAPI`/`GameplayAPI` |
| Физика | Своя верле-леска + импульсы — 200 строк, вместо тяжёлого физдвижка |

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Phaser 3** | Всё из коробки: сцены, ввод, тайлмапы, аудио | Больше вес, меньше контроля над рендером | Годная замена, если команда уже знает Phaser |
| **Godot 4 (web export)** | Удобный редактор, сцены, готовые плагины Яндекс SDK | Пустой web-билд ~5 МБ сжатого, типовой проект 15–25 МБ; долгий старт wasm; на слабых мобилках просадки | Только если у команды сильная экспертиза в Godot |
| **Unity WebGL** | Зрелая экосистема, C# | Пустой 3D-билд ~10 МБ, реальные проекты 30–50 МБ; тяжёлый старт и слабая мобильная производительность в вебе | **Не рекомендуется** для этого проекта |
| **Three.js + Rapier (3D)** | Ближе к оригиналу визуально | Управление одной рукой ломается, риск по FPS и весу, дольше в разработке | Не для MVP |

Решение зафиксировано в [ADR-0001](adr/0001-stack.md) — там же полный список библиотек с
лицензиями и трёхдневный спайк, который подтверждает или опровергает выбор до фазы 1. Смена стека
после вертикального среза недопустима.

### Физика — это подача, а не источник истины

Исход боя считает детерминированная система на данных: натяжение растёт по формуле, усталость
рыбы падает по формуле, паттерн рывков лежит в `content/fish.json`. Верле-леска, изгиб удилища и
рывки камеры — визуализация уже посчитанного результата.

Симуляция, из которой выводится исход, невоспроизводима, не поддаётся балансировке и меняет
поведение при просадке FPS — игрок проигрывает из-за железа. Плюс у нас лидерборды:
недетерминированный бой означает нечестные рекорды.

Правило для кода: `FightSystem` работает на фиксированном шаге симуляции и ничего не знает о
рендере; `LineRope` читает его состояние и никогда в него не пишет.

## 4.3 Слой платформы

Весь код Яндекс SDK живёт только в `platform/YandexPlatform.ts`. Игровая логика знает лишь
интерфейс `IPlatform`. Это даёт локальную разработку без портала и делает будущий порт (VK Play,
CrazyGames, Playdeck) вопросом одного файла.

```ts
export interface IPlatform {
  init(): Promise<void>;
  ready(): void;                     // LoadingAPI.ready()
  gameplayStart(): void;             // GameplayAPI.start()
  gameplayStop(): void;              // GameplayAPI.stop()
  lang(): string;
  isTV(): boolean;
  showRewarded(placement: string): Promise<boolean>;
  showInterstitial(): Promise<void>;
  showBanner(): Promise<void>;
  hideBanner(): Promise<void>;
  load(): Promise<SaveData | null>;
  save(data: SaveData): Promise<void>;
  submitScore(board: string, value: number): Promise<void>;
}
```

### Подключение SDK

Скрипт SDK подключается в `index.html` **до** вызова `YaGames.init()`:

```html
<script src="/sdk.js"></script>
```

```ts
// YandexPlatform.ts
async init() {
  this.ysdk = await YaGames.init();
  this.player = await this.ysdk.getPlayer();      // гостевой режим допустим
  this.locale = this.ysdk.environment.i18n.lang;  // автоопределение языка
}

ready() { this.ysdk.features.LoadingAPI?.ready(); }
gameplayStart() { this.ysdk.features.GameplayAPI?.start(); }
gameplayStop() { this.ysdk.features.GameplayAPI?.stop(); }
```

> Авторизацию через `ysdk.auth.openAuthDialog()` вызываем **только по кнопке** («Сохранить прогресс
> в облаке», «Участвовать в рейтинге») — требование платформы про осознанное действие. До этого
> играем в гостевом режиме и храним прогресс локально.

### Реклама

```ts
async showInterstitial() {
  this.game.pause();
  this.audio.muteAll();
  this.gameplayStop();
  await new Promise<void>(resolve => {
    this.ysdk.adv.showFullscreenAdv({
      callbacks: { onClose: () => resolve(), onError: () => resolve() },
    });
  });
  this.audio.unmuteAll();
  this.game.resume();
  this.gameplayStart();
}
```

Правила `AdManager`:
- кулдаун полноэкранной рекламы — не менее 180 секунд и только вне активного геймплея;
- rewarded — без кулдауна, но каждая точка показывает награду **до** запуска ролика;
- награда выдаётся строго в `onRewarded`, а не в `onClose`;
- если `wasShown === false` — награду не выдаём, но и не наказываем игрока.

### Сохранения

```ts
// SaveService: локальный кэш — источник правды в рантайме, облако — синхронизация
save(data: SaveData) {
  localStorage.setItem(KEY, JSON.stringify(data));   // мгновенно
  this.scheduleCloudFlush();                          // дебаунс 10 сек
}
```

- Лимиты SDK: `setData` — 100 запросов / 5 минут, ≤ 200 КБ. Дебаунс 10 секунд с гарантированным
  флашем перед показом рекламы, на `visibilitychange` и `pagehide`.
- Формат сейва версионируется (`{version: 3, ...}`), миграции — чистые функции `migrate_2_to_3`.
- Числовые агрегаты (крупнейшая рыба, всего поймано) дублируем в `setStats` — дешевле и быстрее.
- При старте: локальный сейв ↔ облачный, побеждает больший `updatedAt`; конфликт разрешаем в
  пользу игрока (максимум по каждому счётчику).

### Аудио и фокус

Требование платформы: звук останавливается при потере фокуса. Реализуем один раз в `AudioService`:

```ts
document.addEventListener('visibilitychange', () => {
  document.hidden ? this.suspend() : this.resume();
});
window.addEventListener('blur', () => this.suspend());
window.addEventListener('focus', () => this.resume());
```

Плюс `GameplayAPI.stop()` при уходе и `start()` при возврате. Форматы: `.ogg` + `.m4a` (Safari),
общий бюджет звука — 3 МБ.

## 4.4 Бюджеты производительности

| Показатель | Бюджет |
|---|---|
| Вес архива (распакованный) | ≤ 25 МБ (лимит платформы 100 МБ) |
| Время до первого экрана | ≤ 3 сек на 4G |
| Время до `LoadingAPI.ready()` | ≤ 6 сек |
| FPS на Redmi 9A / iPhone SE 2020 | ≥ 30 стабильно, целевые 60 на среднем сегменте |
| Draw calls на кадр | ≤ 40 (всё через атласы) |
| Пиковая память | ≤ 250 МБ |
| Спрайтовые атласы | ≤ 2048×2048, формат WebP + PNG-фолбэк |

Ассеты локаций 2–5 догружаются лениво при первом входе, чтобы не раздувать стартовый пакет.

## 4.5 Адаптивность и ввод

- **Портрет (мобильные, приоритет):** вертикальный разрез воды, вся управляющая зона — нижняя
  треть экрана, игра проходится **одним большим пальцем**.
- **Ландшафт (десктоп):** та же сцена, шире по горизонтали; соотношение активного поля держим в
  пределах 2:1 (требование платформы). Управление мышью, пробел/стрелки как альтернатива.
- **TV:** навигация стрелками пульта, обработка OK и Back, фокус-рамка на всех интерактивных
  элементах, магазин скрыт (покупки на TV запрещены).
- Отключаем контекстное меню в игровой области (`contextmenu` → `preventDefault`) — частая
  причина отказа модерации.
- Никакого системного скроллбара: `html, body { overflow: hidden; overscroll-behavior: none; }`.

## 4.6 Инструменты и процесс

- **Сборка:** Vite → `dist/` → `tools/build-zip.ts` пакует ZIP и **проваливает сборку**, если
  распакованный размер > 100 МБ, есть кириллица/пробелы в именах или отсутствует `index.html`
  в корне.
- **Локальная разработка:** `LocalPlatform` подменяет SDK (реклама — заглушка на 2 секунды,
  сейвы — localStorage), поэтому портал не нужен до самого тестирования черновика.
- **CI (GitHub Actions):** typecheck + eslint + unit-тесты баланса и `CatchResolver` + сборка ZIP
  как артефакт PR.
- **Тестирование на площадке:** черновик в консоли работает с реальной рекламой, авторизацией и
  облачными сохранениями — обязательный этап перед отправкой.
- **Аналитика:** собственные события (воронка первых 10 минут, точки rewarded, обрывы лески,
  прохождение боссов) + метрики консоли разработчика. Сторонние рекламные SDK запрещены.
